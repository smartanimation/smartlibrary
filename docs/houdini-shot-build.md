# Houdini Shot WORK STAGE

Build Manager now offers DCC = Maya / Houdini. Select Houdini, Shot, WORK STAGE and the intended department/task, then Build Selected. Existing Maya workers and review output processing are unchanged.

Houdini consumes enabled environment inputs from the common Construct, including saved context, exclusions and fixed Release choices. The existing AssetPublishResolver resolves the common USD Pack. For a fixed Release choice, the resolver selects the newest completed Pack referencing that exact Release. If no completed Pack includes it, Build is blocked. A newer Pack never silently replaces a fixed Release choice. Planned Snapshot / USD Build Snapshot displays the fixed entry path, Pack version, Release version, variant, quality, timing and placement matrix.

The queued job captures those values; the worker never resolves latest again. USD and timing input hashes are checked before Build and after save. Each placement has a separate Xform parent, preserving the referenced asset root transform. Names must be unique USD identifiers. The current transform defaults to identity; published placement and camera inputs are explicitly blocked until their DCC adapters are implemented.

Output directories and artifact paths use existing ProjectPaths. Each version under shot_build_dir(..., department, houdini, task, version) contains {shot}_{department}_{task}_{version}.hip, shot.usda, job.json, status.json and a successful build_manifest.json. Failed jobs have no completed manifest and are retried as a new Build version. The worker reopens the saved HIP before reporting success. Open the reported HIP in Houdini. The scene basename matches Maya, changing only the extension (for example test01_layout_preComp_v001.hip).

Runtime comes from the project's software_Houdini*.yml registration, using hython beside the registered Houdini executable. If there are multiple registrations, set build_worker.houdini_config in project_settings.yml to the selected software configuration filename.

Initial scope: static environment USD and published editorial timing, Shot / WORK STAGE. Unsupported enabled animation, camera, placement, audio and other scene inputs block Build with a reason. Review-layer metadata is not consumed in WORK STAGE. Sequence, UPDATE, REND STAGE, Accept to Work, movie output and automatic GUI launch are not added by this change.


## Crowd work area generated by Build

The same HIP now includes a SOP work area:

- `/stage/OUT_BACKGROUND`: background-only branch used by LOP Import. Never feed final crowd composition back into this branch.
- `/stage/OUT_REVIEW`: currently forwards the background. Future crowd/FX imports connect downstream of the background input.
- `/obj/crowd_environment/OUT_BACKGROUND_METERS`: packed USD primitives with preserved USD `path`, converted once to meters and Y-up.
- `/obj/crowd_environment/SELECT_FLOOR` and `SELECT_OBSTACLES`: primitive Group Expression nodes. Their initial expression is `0` (empty). Set expressions matching the preserved path, e.g. `s@path == "/World/.../floorMesh"`, or replace these with artist-authored primitive selections. Build does not guess walkable surfaces or obstacles.
- `/obj/crowd_environment/OUT_FLOOR` and `OUT_OBSTACLES`: selected geometry in meters/Y-up.
- `/obj/crowd_source/OUT_PLACEMENT_SURFACE`: Object Merge of the selected floor, ready for placement points/Crowd Source. No agents or solver are instantiated yet.
- `/obj/crowd_publish/IN_CROWD_METERS`: connection point for a future crowd cache. `OUT_CROWD_STAGE` applies the inverse unit/up-axis transform, ready for downstream Solaris import.

The background SOP import is static at shot start. For a cm/Y-up project, work geometry scales by 0.01 and the publish connection scales by 100. For Z-up input, work additionally rotates -90 degrees about X, with the inverse on output. Stage assets themselves are unchanged. The working and inverse conventions and validation bounds are recorded in build_manifest.json.

Build validates nonempty packed USD background with prim paths and usable output nodes, both before save and after reopening. Floor/obstacle/source outputs intentionally remain empty until selected. Group edits made while checking output are not automatically saved into the immutable Build.

Background display stays packed. Floor/obstacle groups select mesh-level USD packed primitives first; only selected meshes enter UNPACK_FLOOR / UNPACK_OBSTACLES. Both selections default to empty. No full-background Unpack is cooked by default.

Asset Release versions for scene Build are selected in Build Contents / Build Version. The selection is persisted as a context-scoped asset_version_locked choice in the shot Construct and consumed by Maya and Houdini resolution. Review Planned Snapshot does not override the Houdini scene Build asset choice. Changing the asset quality context releases the previous context's path selection.
